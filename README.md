# ローポリ化 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-LowPolyAbstraction.svg)](https://github.com/routersys/YMM4-LowPolyAbstraction/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材を三角形の面で塗り分けてローポリ画として描画する映像エフェクトプラグインです。
エッジの上に頂点を固定し、残りの頂点を、エッジからの距離に応じて重みを付けた重心ボロノイ分割で並べ、色の誤差が大きい三角形をさらに分割します。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
三角形の配置は素材とシードから決定論的に決まり、同じ設定では常に同じ形になります。
強さ、細かさ、輪郭忠実度、細分化、グラデーション、輪郭線、彩度、明度ゆらぎの8項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「ローポリ化」として表示されます。カテゴリは装飾と加工です。

入力された現在のフレームを、長辺が品質で決まる画素数に収まるように縮小し、輝度と不透明度からエッジを求めます。エッジの上に頂点を固定し、残りの頂点を、エッジからの距離に応じて重みを付けた重心ボロノイ分割で並べます。並べた頂点を結んで、素材を三角形に分けます。この頂点の置き方は、Gai and Wangの論文「Artistic Low Poly rendering for images」（The Visual Computer、2016年）に基づきます。色の誤差は、三角形の中の画素の輝度のばらつきを表す分散です。色の誤差が大きい三角形をさらに分割する処理は、Lawonn and Güntherの論文「Stylized Image Triangulation」（Computer Graphics Forum、2019年）に基づきます。三角形の塗りは、縮小する前の素材の解像度で描きます。配置の計算は決定論的で、時間値や実行のたびに変わる乱数を使用しません。同じ素材、同じシード、同じパラメータからは常に同じ配置になります。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへの画素の読み戻しを行わず、16個の整数の読み戻しだけで素材の変化を判定します。三角形を描くのは、素材の不透明な部分を囲む矩形に余白を加えた範囲だけです。素材の大きさと色と不透明度、三角形の配置を決めるパラメータが変わらないフレームでは、三角メッシュの計算を再利用します。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-LowPolyAbstraction/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「ローポリ化」を選択してください。

## 主な機能

### 1. エッジに沿う三角メッシュ

エッジは、輝度や不透明度が急に変わる所です。素材の輪郭と、輝度の違う色の境界がこれに当たります。本プラグインは、輝度と不透明度を足した値が急に変わる所をエッジとし、ソーベルフィルタで求めます。輝度が同じで色だけが違う境界はエッジとして求まりにくく、三角形の辺として残りにくくなります。

頂点には、エッジの上に固定する頂点と、内側で動かす頂点の2種類があります。エッジの上の頂点は、素材を区切った格子のセルごとに、最もエッジの強い画素へ1つずつ置きます。エッジの上にない頂点を、内側の頂点と呼びます。内側の頂点は、別の格子のセルごとに1つずつ、シードで決めた位置に置いてから動かします。画素の不透明度が5%以下の所には、どちらの頂点も置きません。

ボロノイ図は、各画素を最も近い頂点に割り当てて領域に分けた図です。各頂点が自分の領域の重心に一致するボロノイ図を、重心ボロノイ分割と呼びます。内側の頂点は、Lloyd法で重心ボロノイ分割に近づけます。Lloyd法は、各頂点を自分の領域の重心へ動かし、ボロノイ図を求め直すことを繰り返す方法です。重心は画素ごとの重みを掛けて求めるので、頂点は重みの大きい所へ寄ります。重みはエッジからの距離に応じて周期的に上下し、上下の幅はエッジから離れるほど小さくなります。重みの大きい帯はエッジと平行に並ぶので、内側の頂点はこの帯に沿って列を作ります。

三角形は、画素単位で求めたボロノイ図から作ります。3つの領域が接する所ごとに、その3つの領域の頂点を結んで三角形にします。エッジの上の頂点は動かないので、素材の輪郭と色の境界は三角形の辺として残り、エッジに沿って三角形が帯状に並びます。三角形は頂点どうしを結んで作るので、素材のくぼみや隙間をまたぐことがあります。そのため、三角形ごとに覆う画素の不透明度を調べ、5%以下の画素が過半を占める三角形は描きません。

### 2. 細かさとシード

細かさは、頂点の数の目安を決めます。細かさが0%のときは頂点数の基準の10分の1、100%のときは基準と同じ数が目安です。頂点数の基準は品質ごとに決まり、「品質の選択」の表にあります。低いほど大きな三角形で大胆に抽象化され、高いほど細かく分割されます。目安は素材の大きさによらないので、小さな素材ほど三角形も小さくなります。素材に透明な部分が多いほど、実際の頂点の数は目安より少なくなります。

シードは、内側の頂点を初めに置く位置と、明度ゆらぎの模様を決める固定値です。

### 3. 輪郭忠実度

輪郭忠実度は、エッジの上に置く頂点の間隔と、エッジからの距離に応じた重みの上下の幅を決めます。高いほど、エッジの上の頂点の間隔が狭まって数が増え、内側の頂点もエッジに沿った列へ強く集まります。その結果、素材の輪郭と色の境界が三角形の辺として保たれます。0%では重みが一様になり、内側の頂点は素材の中へ均等に散らばります。エッジの上の頂点も減り、色の境界をまたぐ大きな三角形が増えます。

### 4. 色の誤差に応じた細分化

細分化は、色の誤差が大きい三角形を分割する強さを決めます。色の誤差は、三角形の中の画素の輝度のばらつきを表す分散です。細かさが全体の頂点の数を決めるのに対し、細分化は色の誤差が大きい所にだけ頂点を足します。

色の誤差がしきい値を超えた三角形の重心へ新しい頂点を足し、Lloyd法で頂点を2回動かしてから三角形を作り直します。細分化を上げるほどしきい値が下がり、分割する三角形が増えます。細分化を0%にしても分割は止まらず、色の誤差が特に大きい三角形は分割します。

この分割を品質で決まる回数だけ繰り返すと、色の変化が細かい所ほど三角形が細かくなり、平坦な所は大きな三角形のまま残ります。足した頂点を合わせても、頂点の数は細かさで決まる目安の1.5倍までです。

### 5. 塗りとグラデーション・輪郭線・彩度・明度ゆらぎ

各三角形は、中の画素の色の平均で一色に塗ります。ただし、輝度が三角形の中の輝度の平均から大きく外れた画素は、色の平均に含めません。外れたとみなすのは、平均との輝度の差が標準偏差の1.2倍を超える画素です。標準偏差は、ばらつきの目安です。三角形の中の少数の明るい画素や暗い画素に、色が引きずられにくくなります。不透明度が5%以下の画素も含めません。塗りは縮小する前の素材の解像度で描くので、縮小して計算しても三角形の辺はぼやけません。

グラデーションは、三角形の中で色を滑らかに変える割合です。三角形ごとの一色の塗りに、頂点の色から補間した塗りを混ぜます。頂点の色は、その頂点の領域にある画素の平均の色です。0%では三角形ごとに一色、100%では三角形の中で色が滑らかに変わります。

輪郭線は、三角形の辺に沿って入れる暗い線の濃さです。素材の輪郭だけでなく、すべての三角形の辺に線を入れます。線は縮小する前の解像度で辺から1.5画素までの範囲に入り、辺から離れるほど元の明るさに戻ります。値を上げるほど線は暗くなり、100%では辺の真上の明るさが元の35%になります。

彩度は、三角形の色を鮮やかにする量です。0%では元の色のまま、100%では同じ輝度の灰色からの色の差を1.6倍にします。

明度ゆらぎは、三角形ごとに明るさを変える量です。100%では三角形ごとに明るさを最大8%上げ下げし、平坦な所でも三角形の面が見分けられるようにします。ゆらぎは三角形の重心とシードから決定論的に決まります。

### 6. 品質の選択

品質は、作業解像度、頂点数の基準、Lloyd法の反復回数、分割の反復回数をまとめて切り替えます。作業解像度は、縮小して計算するときの長辺の画素数の上限です。頂点数の基準が変わるので、同じ細かさでも品質を変えると三角形の数が変わります。

| 品質 | 作業解像度 | 頂点数の基準 | Lloyd法の反復 | 分割の反復 |
|---|---:|---:|---:|---:|
| 標準 | 1024 | 4096 | 6回 | 1回 |
| 高品質 | 1536 | 8192 | 8回 | 2回 |
| 最高品質 | 2048 | 16384 | 10回 | 3回 |

表のLloyd法の反復は分割の前に行う回数で、分割のたびに行う2回は含みません。

縮小するかどうかは、透明な部分も含む素材全体に余白を加えた計算領域の長辺で決まります。計算領域の長辺の画素数が作業解像度を超えるときは、長辺が作業解像度になるように縮小して計算し、短辺は縦横比に合わせます。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 三角メッシュの生成には現在のフレームの色と不透明度だけを使用します。履歴フレーム、外部画像、学習済みモデルは使用しません。画素の不透明度が5%以下の所は、頂点の配置と色の計算に使いません。素材のすべての画素の不透明度が5%以下のときは、エフェクトを適用せず入力映像を表示します。
- 計算領域は、透明な部分も含む素材全体の矩形の上下左右に8画素の余白を加えた大きさで、長辺は8192画素が上限です。素材の長辺が8176画素を超える場合は、エフェクトを適用せず入力映像を表示します。
- 処理量とGPUメモリ使用量は、計算領域の大きさと品質に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は作業解像度と反復回数が最も多いため、高品質と標準より処理負荷が高くなります。描画の計算は、素材の不透明な部分を囲む矩形に余白を加えた範囲に限ります。
- キャッシュ: 素材の大きさと色と不透明度、品質、シード、細かさ、輪郭忠実度、細分化が変わらないフレームでは、三角メッシュの計算を再利用します。強さ、グラデーション、輪郭線、彩度、明度ゆらぎだけを変えたフレームでは、三角メッシュを計算し直しません。動画や口パクのように素材の内容が変わるフレームと、細かさ、輪郭忠実度、細分化をアニメーションで変えたフレームでは、毎回計算し直すので処理が重くなります。素材が変わったかどうかを調べる計算は、再利用するフレームでも毎フレーム行います。
- 強さ0%: 強さが0%のときは入力を変更しません。
- シードと再現性: 三角形の配置は、シード、セル位置、素材の内容から決定論的に算出します。時間値は生成に使用しません。素材の内容が変わるフレームや、細かさ、輪郭忠実度、細分化をアニメーションで変えたフレームでは、三角形の配置も変わることがあります。
- 透明部分: 不透明度が5%以下の画素が過半を占める三角形は描かないので、素材のくぼみや隙間は透明のまま残ります。ただし、三角形より細かい隙間は三角形で塗られます。くぼみや隙間の際では、描いた三角形の一部がはみ出すことがあります。出力範囲は計算領域に収まります。ローポリ画は元映像の上へアルファ合成し、三角形で覆われない画素では元映像がそのまま見えます。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、計算領域が上限を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | GitHubへ接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
