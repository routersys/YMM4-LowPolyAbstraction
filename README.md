# ローポリ化 for YMM4

[![License](https://img.shields.io/badge/license-MIT-blue.svg)](#)
[![.NET](https://img.shields.io/badge/.NET-10.0-purple.svg)](#)
[![Release](https://img.shields.io/github/v/release/routersys/YMM4-LowPolyAbstraction.svg)](https://github.com/routersys/YMM4-LowPolyAbstraction/releases)

---

YukkuriMovieMaker4（YMM4）上で動作する、素材を三角メッシュへ抽象化してローポリ調に描画する映像エフェクトプラグインです。
エッジ拘束と特徴フロー場つきの重み付きボロノイ緩和で頂点を最適化し、色の誤差が大きい三角形を細分化して細部へ密度を寄せます。
履歴フレーム、参照画像、学習済みモデルを使わず、入力された一枚の映像だけを処理します。
三角形の配置はシードから決定論的に決まり、同じ設定では常に同じ形になります。
強さ、細かさ、輪郭忠実度、細分化、グラデーション、輪郭線、彩度、明度ゆらぎの8項目はアニメーションに対応しています。

## 概要

本プラグインはYMM4の映像エフェクトとして動作し、エフェクトの種類一覧では「ローポリ化」として表示されます。カテゴリは装飾と加工です。

入力された現在のフレームを作業解像度へ縮小し、輝度とアルファのSobel勾配からエッジを抽出します。頂点の配置はGai and Wangの論文「Artistic Low Poly rendering for images」（2016年）に基づき、エッジまでの距離場から作る特徴フロー場を重みとした重心ボロノイのLloyd緩和で最適化します。エッジ上の拘束点は固定し、内部点だけを動かすことで、輪郭が三角形の辺として保たれます。三角形はボロノイ割り当て図の双対として求め、三角形ごとに刈り込み平均で色を集計します。輝度分散が大きい三角形の重心へ新しい頂点を挿入する細分化は、Lawonn and Güntherの論文「Stylized Image Triangulation」（2019年）の高誤差三角形分割に基づきます。

生成は決定論的で、乱数と時間値を使用しません。同じ素材、同じシード、同じパラメータからは常に同じ三角メッシュになります。

計算はComputeWeaveの計算シェーダーがDirect3D 12で実行します。YMM4のDirect3D 11側とComputeWeaveのDirect3D 12側は、共有テクスチャと共有フェンスで接続します。通常のフレーム処理では、CPUへの画素の読み戻しを行わず、内容ハッシュとバウンディングボックスだけを読み戻します。素材が存在する矩形の範囲だけを描画し、素材の内容とメッシュを決めるパラメータが変わらないフレームでは三角メッシュの計算を再利用します。

このエフェクトはAviUtl向けのEXO出力には対応していません。

## インストール方法

1. [Releases](https://github.com/routersys/YMM4-LowPolyAbstraction/releases/latest)ページから最新のプラグインファイル（`.ymme`）をダウンロードしてください。
2. YMM4が起動していないことを確認し、ダウンロードしたファイルを実行してインストールします。
3. YMM4を起動し、タイムライン上のアイテムに映像エフェクトを追加します。
4. 映像エフェクトの種類として「ローポリ化」を選択してください。

## 主な機能

### 1. 三角メッシュ化

素材のアルファ値が示すシルエットの内側へ頂点を配置し、ボロノイ割り当て図の双対として求めた三角メッシュで素材を覆います。各三角形は、内部の画素色の刈り込み平均で塗られます。刈り込み平均は輝度の平均±1.2σの帯域内の画素だけを使うため、明部と暗部が混ざった三角形でも中間色に濁りません。

頂点の配置は重み付き重心ボロノイのLloyd緩和で最適化します。重みはエッジまでの距離の三角波で、頂点がエッジに平行なレーンへ整列し、輪郭に沿った三角形の帯ができます。

### 2. 細かさとシード

細かさは、三角形の目標数を決めます。低いほど大きな三角形で大胆に抽象化され、高いほど細かく分割されます。

シードは、内部頂点の初期配置のジッターを決める固定値です。頂点の配置はシード、セル位置、素材の内容から決定論的に算出するため、同じ設定では常に同じメッシュになります。

### 3. 輪郭忠実度

輪郭忠実度は、エッジ上の拘束点の密度と、特徴フロー場の重みの強さを決めます。高いほどエッジのサンプル間隔が狭まり、頂点がエッジへ強く引き寄せられるため、素材の輪郭と色の境界が三角形の辺として保たれます。低いほど頂点が一様に近づき、境界を跨ぐ大きな三角形が増えます。

### 4. 誤差駆動の細分化

細分化は、色の誤差が大きい三角形を分割する強さを決めます。三角形ごとに輝度の分散を集計し、閾値を超えた三角形の重心へ新しい頂点を挿入して、ボロノイ緩和と三角化をやり直します。この反復により、色の変化が細かい領域へ三角形の密度が寄り、平坦な領域は大きな三角形のまま保たれます。

### 5. グラデーション・輪郭線・彩度・明度ゆらぎ

グラデーションは、三角形内の塗りを平坦塗りから頂点色の線形補間へ混ぜる割合です。0%では完全な平坦塗り、100%では滑らかなグラデーション塗りになります。

輪郭線は、三角形の境界線の濃さです。値を上げると辺に沿って暗い線が入り、ステンドグラスやワイヤーフレームの趣になります。

彩度は、三角形の色の彩度の強調量です。明度ゆらぎは、三角形ごとの明るさの微小な変動で、平坦な領域でも三角形の面が見分けられるようになります。ゆらぎは三角形の重心とシードから決定論的に決まります。

### 6. 品質の選択

品質は、作業解像度、頂点数の基準、Lloyd緩和の反復回数、細分化の反復回数をまとめて切り替えます。

| 品質 | 作業解像度 | 頂点数の基準 | 緩和反復 | 細分化反復 |
|---|---:|---:|---:|---:|
| 標準 | 1024 | 4096 | 6回 | 1回 |
| 高品質 | 1536 | 8192 | 8回 | 2回 |
| 最高品質 | 2048 | 16384 | 10回 | 3回 |

作業解像度は計算領域の長辺の画素数です。短辺は計算領域の縦横比に合わせて決めます。

## 制限事項

- AviUtl向けのEXO出力には対応していません。
- Direct3D 12デバイスを取得できない場合や、YMM4が使うDirect3D 11デバイスとの共有テクスチャおよび共有フェンスを作成できない場合は、エフェクトを適用せず入力映像を表示します。
- 三角メッシュの生成には現在のフレームの色とアルファ値だけを使用します。履歴フレーム、外部画像、学習済みモデルは使用しません。
- 計算領域は素材の範囲に固定余白8画素を加えた大きさで、長辺は8192画素が上限です。素材が大きすぎる場合は、エフェクトを適用せず入力映像を表示します。
- 処理量とGPUメモリ使用量は、計算領域の大きさと品質に応じて増えます。

## 注意事項

- 処理負荷: 最高品質は作業解像度と反復回数が最も多いため、高品質と標準より処理負荷が高くなります。三角メッシュの再計算は素材の内容が変わったフレームだけで実行され、変わらないフレームでは描画だけを行います。描画は素材が存在する矩形の範囲だけを計算します。
- キャッシュ: 素材の内容と、品質、シード、細かさ、輪郭忠実度、細分化が変わらないフレームでは、三角メッシュの計算を再利用します。グラデーション、輪郭線、彩度、明度ゆらぎだけを変えたフレームでは、メッシュを再計算しません。
- 強さ0%: 強さが0%のときは入力を変更しません。
- シードと再現性: 三角形の配置は、シード、セル位置、素材の内容から決定論的に算出します。時間値は生成に使用しません。
- 出力範囲: 三角形は素材のシルエットの内側に生成されるため、出力範囲は素材の範囲に余白を加えた矩形に収まります。ローポリ画は元映像の上へアルファ合成します。
- 更新通知: エフェクトを最初に生成したときに、YMM4の実行中に一度だけ新しい正式版を確認します。更新情報を取得できない場合は通知せず、そのまま動作します。プレリリースは通知の対象に含めません。
- 不具合の自動送信: 想定していない例外が起きたときは、その内容を開発者へ自動で送信します。内容は「不具合の報告」に書いています。
- 本プラグインを使用する前に、YMM4のプロジェクトファイルのバックアップを作成することを推奨します。

## 不具合の報告

本プラグインは、想定していない例外が起きたときに、その内容を開発者へ自動で送信します。同意は求めず、常に送信します。

送信する情報は次のとおりです。

| 種類 | 内容 |
|---|---|
| 例外 | 型の完全名、メッセージ、スタックトレース |
| 発生位置 | モジュール名、関数名、ファイル名、行番号 |
| プラグイン | アセンブリ名、バージョン |
| 実行環境 | OSの名前とバージョン、.NETのバージョン、CPUのアーキテクチャ、論理プロセッサ数 |
| 識別子 | YMM4の起動ごとに決まるセッション識別子、報告ごとの識別子 |

メッセージとファイル名は、送信の前に置き換えを通します。置き換えるのは、Windowsのユーザー名、ユーザーフォルダー、AppDataのパス、マシン名、ドメイン名、メールアドレス、IPv4アドレスです。送信元のIPアドレスは受信側へ渡す手前で取り除いています。

映像の中身とプロジェクトの内容は送信しません。継続して個人を追跡する識別子も持ちません。セッション識別子はYMM4を起動し直すと別の値になります。

送信するのは想定していない例外だけです。YMM4が本プラグインのエフェクトを作るとき、フレームごとに更新するとき、入力をつなぎ直すとき、破棄するときと、Direct2Dがシェーダーの定数を書き込むときに起きた例外を報告し、その後はYMM4へそのまま渡します。画面の操作やバックグラウンドの処理で未処理になった例外も報告しますが、本プラグインのコードが関わる例外に限ります。本プラグインの外で起きた例外は送信しません。

次の失敗は送信しません。

| 種類 | 例 |
|---|---|
| 効果をかけないだけで済ませるもの | Direct3D 12デバイスを取得できない、YMM4のDirect3D 11デバイスとの共有テクスチャや共有フェンスを作成できない、計算領域が上限を超えるときに、エフェクトを適用せず入力映像を表示したとき |
| 更新の確認の通信の失敗 | GitHubへ接続できない |

送信できなかった報告はYMM4のユーザーフォルダーへ退避し、次回の起動時に送り直します。送信も再送も非同期に行うため、起動と描画が遅くなることはありません。

実装は [YMM4-Telemetry](https://github.com/routersys/YMM4-Telemetry) をサブモジュールとして取り込んでいます。
